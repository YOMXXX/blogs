10 月 19 日，MiniMax 正式发布 M3.1 Flash。这不是一次常规迭代：官方给的核心叙事是「智能体性能与成本的重新定义」——在线推理速度提升近三倍，使用成本比上代降低七成。对每天都在给 Agent 算账的团队，这两个数字比任何 benchmark 都更值得停下来看一眼。

## 一分钟速览

- 定价：每百万 token 输入 0.15 美元、输出 0.60 美元、缓存输入 0.015 美元
- 速度：日常使用输出可达 200 tokens/s 以上，中位速度（P50）稳定在 170 tokens/s 以上
- 上下文：100 万 token
- 推理档位：低、中、高、最高四档，常驻开启
- 获取渠道：MiniMax API、M Plan 订阅（Plus 每月 20 美元、Max 50 美元、Ultra 120 美元）、MiniMax Code 桌面客户端
- 权重状态：官方承诺后续开放，当前为专有模型

## 发布背景：先打个悬念再揭晓

这次发布有个漂亮的开场。MiniMax 官方披露：此前匿名运营、累计处理超过 200 万亿 token 的 Space Bunny 服务，正是 M3.1 Flash 的早期版本。也就是说，这个模型先在真实流量里匿名打磨了相当长时间，参数与行为已经被海量请求验证过，再走到台前正式命名。对一款主打智能体的模型，这种「先服役、后授衔」的节奏比直接放 demo 更有说服力。

官方同时预告，同系列的 Pro 型号（推向智能边界）将在后续到来。M3.1 Flash 在这个序列里的角色很清楚：不是旗舰，是量产智能体负载的主力型号。

## 基准拆解：智能体三线加一条安全线

MiniMax 这次公布的基准几乎全部指向智能体负载，我们逐条看含金量。

**AutomationBench-AA**：官方称 M3.1 Flash 跻身顶级表现者行列。这个基准的形态是跨 SaaS 系统的真实企业工作流——销售、营销、运营、客服、财务、人力资源的端到端任务。它考的不是单点能力，而是把一堆企业软件串起来干活的长链条执行力。

**BankerToolBench 76.2 分**：针对金融场景的复杂真实任务，多步规划、跨文档与文件的一致性维持、财务合规、链式工具调用。76.2 这个分数意味着它可以进入「能处理真实工单」的区间，而不是只能做演示。

**DeepSWE v1.1 73.7%**：聚焦复杂软件任务，要求模型独立理解代码库、开发功能、修问题并用测试自我验证。73.7% 的定位是「与顶级模型并列」。对编程 Agent，这个成绩配 0.6 美元每百万输出的定价，性价比是主要卖点。

**OSWorld V2 61.7 分、ALE 29.6 分**：前者考计算机操作与跨应用任务执行，后者考真实专业工作与复杂任务。官方称 M3.1 Flash 在两个基准上均为中国模型第一。ALE 29.6 的绝对分不高，但这个基准整体难度大，参考意义在于横向排名。

**CyberGym 82%**：漏洞发现与验证基准。官方补充说内部安全专家在代码审计、漏洞修补、渗透测试、恶意软件分析与逆向工程上做了深度评估，表现强劲。注意这条对防守方是生产力工具，模型越会找漏洞，防御侧的审计覆盖率就越高——但这类能力天然双刃，选用时请留在授权测试的边界内。

作为第三方参照，daily.dev 的测试显示 M3.1 Flash 在 KingBench 3 编程基准上得 66.25%（80 题中 53 题），相比 M3 的 31.25% 提升 35 个百分点；同场对比中 Anthropic Opus 5.5 为 93.75%。这给了一个清醒的坐标：M3.1 Flash 是「中坚力量」，不是「顶尖高手」，官方自己的措辞也是「达到领先模型水平」而非超越。

## 成本账：把 benchmark 翻译成美元

单看定价，M3.1 Flash 与 Inception Mercury 3 的首发价（0.10 与 0.35 美元）在同一档，且缓存输入 0.015 美元比 Mercury 3 促销期的 0.01 到 0.02 美元也咬得很紧。但 Mercury 3 的首发五折有时效，恢复标价后是 0.20 与 0.70 美元——届时 M3.1 Flash 的 0.15 与 0.60 会重新拉开半个身位。

放到真实负载里算一笔账。一个编程 Agent 每天处理 200 个任务，每任务平均消耗 8 万输入 token 与 4 千输出 token（含代码库上下文与多轮工具调用），按 M3.1 Flash 定价一天的模型成本约为 2.64 美元。如果缓存命中率能做到三成（系统提示与工具定义高度重复），还能再压掉一部分输入开销。官方宣称的「智能体任务整体成本比上代降七成」，主要就来自更激进的稀疏化推理优化加上这个定价结构。

速度侧还有个细节：官方称日常输出可达 200 tokens/s 以上、P50 稳定 170 tokens/s 以上，而 API 文档给的口径是「约 150 tokens/s，实际取决于负载与输入输出长度」。取保守的 150 算，一个 4000 token 的长回答约 27 秒生成完毕——对 Agent 的每一步决策来说，这个延迟在可接受区间，且智能体场景大量步骤可以并行或异步化。

## 上手路径与注意点

三条获取渠道按人群分：写代码验证用 MiniMax Code 桌面客户端（agent.minimax.io/download，可直接选用 M3.1-Flash-Preview 模型）；日常调用走 MiniMax API（platform.minimax.io）；长期重度使用算一下 M Plan 订阅（Plus 20 / Max 50 / Ultra 120 美元每月）与按量付费的盈亏平衡点。

API 调用时注意两点。其一，推理档位常驻开启且有低、中、高、最高四档，建议从「中」起步，按任务 A/B 后再固定——智能体的大量步骤是短决策，「低」档往往就够，把「高」留给规划与汇总步骤。其二，该模型目前是预览版形态（M3.1-Flash-Preview），公开 API 文档的部分页面仍在列旧款 M3，接入时以平台控制台的模型列表为准。

一个待观察项：权重「稍后发布」是官方承诺但无时间表。如果最终兑现，它会是开源社区一个颇具竞争力的智能体底座；如果延期，按当前定价它依然留在候选池里，只是少了一份「可自托管」的保险。

## 适合谁，不适合谁

适合的画像很明确：token 消耗大的智能体负载——跨系统工作流自动化、长序列编程任务、计算机操作、安全审计辅助。这些场景步骤多、总成本敏感、对单步极限质量要求相对宽容，M3.1 Flash 的成本结构正好卡位。

不适合的画像同样明确：追求单点极限质量的场景。Opus 5.5 在 KingBench 3 上 93.75% 对 66.25% 的差距是真实存在的，把最难的架构设计或复杂推理步骤交给它并不经济。更聪明的用法是分层：规划与难题用顶级模型，执行与批量步骤用 M3.1 Flash——这恰是官方「成本降七成」叙事想要服务的架构。

## 小结

M3.1 Flash 是一款定位极其清晰的模型：不争单项冠军，专攻智能体负载的总拥有成本。0.15 与 0.60 美元的定价、200 tokens/s 级的速度、1M 上下文、73.7% 的 DeepSWE 与 82% 的 CyberGym，组合起来是一个很难忽视的「量产型」选项。加上 Space Bunny 200 万亿 token 的真实流量背书，它的成熟度比多数新发布模型更可信。建议把手上步骤最多的那条 Agent 链路搬过去跑一周，用真实的完成率和账单做最终判断。
