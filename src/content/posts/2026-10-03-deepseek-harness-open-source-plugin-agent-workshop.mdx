10 月 2 日，DeepSeek 做了一件比发新模型更值得开发者关注的事：把自家的 Agent 执行框架 **DeepSeek Harness（DSH）** 推向全球公测，并且直接开源。Hacker News 上相关帖子一天冲到 380 分，讨论的焦点不是模型又强了多少，而是一个更结构性的问题——当模型能力趋同之后，**harness 本身开始成为产品**。

这篇实战带你把 DSH 跑起来，看清它的插件架构，最后聊聊它在当下 Agent 工具版图里的位置。

## 它到底是什么

用一句话定义：DeepSeek Harness 是一个「一切皆插件」的开源 Agent 工作台，有桌面应用和 Web UI 两种形态。

它能干的活覆盖四类：

1. **日常事务**：整理文件、分析表格、起草文档、做幻灯片；
2. **编码**：探索仓库、修 Bug、写特性、跑测试；
3. **研究**：检索信息、核实事实、给出引用；
4. **后台任务**：跑脚本、批量处理文件、跟踪进度。

这些能力不是靠一个巨型系统提示词堆出来的，而是拆成了可组合、可替换、可自建的插件。官方把它构建在 [Cordis](https://github.com/cordiverse/cordis) 框架之上——这是一个「everything is a plugin」的运行时，服务、工具、界面组件都以插件形式装载。

## 五分钟跑起来

 最快路径只需要 Node.js：

```zsh
npx @deepseek-ai/dsh web
```

执行后本地起一个 Web UI，浏览器里直接开聊。首次会话默认加载 DeepSeek-V4.1-Flash，思考档位可调，界面顶部能切换「Workspace Write」等权限模式。

想看源码或者改造它：

```zsh
git clone https://github.com/deepseek-ai/deepseek-harness
```

桌面版则提供 macOS 与 Windows 安装包，适合不想碰终端的同事。三条路径共用同一套会话与插件体系，桌面端建的自动化任务在 Web UI 里同样可见。

## 插件架构：为什么值得认真看

大多数 Agent 产品的扩展点是「MCP 服务器列表」，而 DSH 把扩展粒度做成了完整的插件包：一个插件可以同时携带**工具、技能描述、界面组件和定时任务**。

举一个官方演示的例子——「Scheduled tasks」插件。装上之后，你可以让 Agent 在指定时间启动任务、按周期重复执行，并在任务面板里查看每次运行的产物。这相当于把 cron + Agent + 结果审阅台打包成了一个可安装的能力，而不是让你自己写调度脚本。

**Creator Mode 是另一个关键设计**：你在对话里说「帮我做一个每周一汇总 GitHub 通知的插件」，Harness 会在对话中生成插件的工具定义与配置，直接挂载进当前会话。生成的插件与手工开发的完全同构，可以继续迭代。这本质上是把「写插件」的门槛降到了「描述需求」。

对开发者来说，更实用的是它自带的**执行轨迹排查工具**：每次工具调用的参数、返回值、耗时与运行时信息都能展开检查。Agent 出错时你看到的是结构化的调用链，而不是一句含混的「任务失败了」。

## 权限与工作区：多任务不混线的秘密

DSH 的界面设计里最容易被忽视但最影响体验的是**工作区与权限的分层**。每个会话绑定一个工作区目录，文件操作、脚本执行都发生在工作区内；界面顶部的权限模式（如 Workspace Write）决定 Agent 能动什么。这意味着你可以同时开三个会话——一个整理下载目录、一个分析数据、一个改仓库代码——互不踩线。

对从 ChatGPT 类对话产品迁移过来的用户，这个心智转变很关键：**DSH 里「会话」不是聊天记录，而是一个带文件系统和权限边界的工作现场。** 关掉窗口任务还在，后台任务插件跑的长活儿随时回来查看。

模型选择上，默认的 DeepSeek-V4.1-Flash 支持思考档位调节，简单问答用低档位省时间，复杂推理切高档位。从官方演示看，不同任务可以绑定不同档位，定时任务同样支持——这是把「成本意识」做进产品而不是留给用户自己算账的做法。

## 上手建议：三个值得马上试的场景

**场景一：周报流水线。** 把散落在各处的数据文件丢进工作区，让 Agent 汇总成季度幻灯片。DSH 的表格分析与文档生成走的是同一套会话上下文，中间结果不用手动搬运。

**场景二：仓库值守。** 结合定时任务插件，让它每天早上扫描指定仓库的 Issues，按优先级整理成清单。这是典型的「低频、可校验、收益稳定」的 Agent 任务，适合拿来验证可靠性。

**场景三：自己的插件。** 用 Creator Mode 造一个对接内部系统的最小插件，走一遍「对话生成、挂载、修改、复用」的闭环。评估一个 Agent 平台能不能用，最好的办法就是看它的扩展闭环顺不顺。

## 它在工具版图里的位置

把本周的开源 Agent 生态连起来看会更有意思：10 月 1 日 Earendil 发布了 Pi Durable，主打长时运行与崩溃恢复的持久化 harness；同一天 arXiv 上出现了 Harness Annealing 论文，研究如何让模型学会在更少外部控制下行动；10 月 2 日 DeepSeek 直接把 harness 做成了开源产品。

三条线索指向同一件事：**模型 Stateless，harness 承载状态、权限、上下文与流程**——这一层正在成为竞争的主战场。DeepSeek 的打法很清晰：模型已经有足够多的用户，把执行框架开源出去，让插件生态长在自己这边。

对普通开发者的实际建议是：把它当成「通用 Agent 工作台的第一候选」来试用，但编码主力工具不必急着迁移。DSH 的编码能力来自通用插件而非深度定制的编码工具链，短期内它最强的场景仍是日常办公自动化与轻量研究。

> **💡 一句话总结**：DeepSeek Harness 的意义不在「又一个 Agent 应用」，而在「Agent 的执行层第一次被大厂以开源插件架构的形式标准化」。值得花一个下午认真跑一遍。
